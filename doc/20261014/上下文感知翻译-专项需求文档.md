# 上下文感知翻译 —— 专项需求文档

- 版本：v1.0
- 日期：2026-10-13
- 目标读者：Coding Agent / 开发者
- 关联文档：《实时语音翻译学习工具-需求文档（PRD）v1.1》—— 本文档为其**增量专项需求**，编号体系独立（FR-Cx），落地时与主 PRD 的 FR-1 / FR-4 / FR-5 对接
- 定位：解决「逐句独立翻译导致的跨句上下文缺失」问题：代词指向断裂（日译中的主语省略尤其严重）、术语/称谓前后不一致、语域风格漂移

---

## 1. 背景与问题定义

主 PRD 的翻译链路（FR-1.4）以 VAD 断句后的单句为最小翻译单元。单句独立请求 LLM 会产生三类典型错误：

| 问题类型 | 现象 | 例 |
|---|---|---|
| 指代断裂 | 代词/省略成分无法还原 | 日语「もう帰った？」无法判断主语是谁；英语 "it" 指代不明 |
| 一致性漂移 | 同一实体/术语前后译名不同 | 人名「ユキ」一会译「雪」一会译「由纪」 |
| 语域漂移 | 文体/敬语等级/氛围不连贯 | 同一场景内简体敬体混用、语气忽冷忽热 |

**选型约束**：实时场景要求不高，**采用轻量方案组合**——滑动上下文窗口＋块级整体翻译＋滚动记忆（术语表＋风格摘要）。**明确不采用**两遍翻译（two-pass re-translation）、共指消解预处理模块等重方案。

## 2. 名词定义

| 术语 | 含义 |
|---|---|
| 翻译块（Block） | 一次 LLM 请求中包含的句子集合，块内句子互相可见 |
| 上下文窗口 | 注入 prompt 的历史内容，含上一块尾部句子（原文＋已确认译文）与滚动记忆 |
| 滚动记忆（Rolling Memory） | 随会话累积更新的实体登记表＋风格设定，跨块携带 |
| 实体登记表 | 已出现的人物名、地名、专有名词及其确定译法的映射表 |

## 3. 功能性需求

### FR-C1 滑动上下文窗口

| 编号 | 需求 | 优先级 |
|---|---|---|
| FR-C1.1 | 翻译第 N 块时，prompt 注入前一块**尾部 K 句**的历史对（原文＋已确认译文），要求模型保持指代与风格一致；历史部分仅作参考，模型只输出当前块的译文 | P0 |
| FR-C1.2 | K 可配置（`context.tail_sentences`，默认 3，范围 0–10），按语言档案可覆盖 | P0 |
| FR-C1.3 | 历史对长度设 token 上限（默认 512 tokens），超出则从最早的历史开始裁剪，保证当前块完整 | P1 |

### FR-C2 块级整体翻译

| 编号 | 需求 | 优先级 |
|---|---|---|
| FR-C2.1 | 翻译请求以「块」为单位，块内多句一次请求完成，模型可自由利用块内上下文 | P0 |
| FR-C2.2 | 分批策略优先按**语义边界**切分：静音间隙超过阈值（默认 1.5s）、场景切换信号、或句数达到上限（默认 8 句，可配置 3–15）三者任一触发成块；不得只按固定句数机械切分 | P0 |
| FR-C2.3 | 块与块之间通过 FR-C1 的尾部重叠保持连续性，重叠句不重复翻译、不重复计费 | P0 |
| FR-C2.4 | 块内每句的译文须与原文逐句对齐返回（结构化 JSON 数组），对齐失败时按 FR-C4.3 降级 | P0 |
| FR-C2.5 | 实时模式与离线批处理（主 PRD FR-2.3）共用同一分块逻辑；离线模式可放宽块上限至 20 句以提升上下文质量 | P1 |

### FR-C3 滚动记忆（术语表＋风格摘要）

| 编号 | 需求 | 优先级 |
|---|---|---|
| FR-C3.1 | 维护**实体登记表**：人名、地名、作品名、专有名词 → 确定译法的映射。新实体首次出现时由 LLM 译出并登记，后续块强制沿用登记译法 | P0 |
| FR-C3.2 | 维护**风格设定**：语域（敬体/简体/口语/书面语）、人物关系（如前后辈）、整体氛围标签。由 LLM 在会话初期推断，之后每块可微调更新 | P0 |
| FR-C3.3 | 滚动记忆随每次翻译请求注入 prompt（以结构化区块形式），模板变量为 `{glossary}` 与 `{style_notes}` | P0 |
| FR-C3.4 | 记忆的更新由 LLM 在同一次翻译响应中附带返回（响应 JSON 含 `glossary_updates` 与 `style_updates` 字段），**不增加额外请求**；本地合并去重 | P0 |
| FR-C3.5 | 记忆容量控制：实体登记表上限 100 条（超出按 LRU 淘汰，近期未命中的优先淘汰）；风格摘要 ≤ 200 字 | P1 |
| FR-C3.6 | 记忆随会话保存与恢复：会话文件内附带 `memory.json`，回放模式重新加载字幕时可选择导入原记忆 | P1 |
| FR-C3.7 | 设置界面可查看、手动编辑、清空当前记忆（修正错误登记的译名后即刻生效） | P1 |

### FR-C4 通用约束与降级

| 编号 | 需求 | 优先级 |
|---|---|---|
| FR-C4.1 | 以上所有上下文机制通过 prompt 模板变量实现，**符合主 PRD FR-5（prompt 外部化）**：新增变量 `{context_history}`、`{glossary}`、`{style_notes}`，模板中缺失这些变量时对应机制自动停用（静默降级为无上下文翻译，日志提示） | P0 |
| FR-C4.2 | 各机制独立开关：`context.tail_sentences=0` 关闭滑动窗口；`context.memory.enabled=false` 关闭滚动记忆；块大小=1 时退化为逐句翻译。三个机制可任意组合 | P0 |
| FR-C4.3 | 块内对齐失败或 JSON 解析失败时：整块重试 1 次；仍失败则该块拆为逐句无上下文翻译兜底，保证字幕流不中断 | P0 |
| FR-C4.4 | 缓存 key（主 PRD FR-4.5）扩展为：语言档案 + 句子哈希 + prompt 模板版本号 + 上下文配置摘要，上下文配置变更后旧缓存自动失效 | P1 |

## 4. 配置规范

新增全局配置节（`config.yaml`），语言档案可按主 PRD §5.3 的机制逐项覆盖：

```yaml
context:
  tail_sentences: 3        # FR-C1 滑动窗口：前块尾部历史句数，0 = 关闭
  history_max_tokens: 512  # FR-C1.3 历史 token 上限
  block:
    max_sentences: 8       # FR-C2 块句数上限（离线模式 20）
    silence_gap_sec: 1.5   # FR-C2.2 触发成块的静音阈值
  memory:
    enabled: true          # FR-C3 滚动记忆总开关
    glossary_max_entries: 100
    style_max_chars: 200
```

Prompt 模板新增可用变量（写入模板文件头注释）：

| 变量 | 内容 | 来源 |
|---|---|---|
| `{context_history}` | 前块尾部 K 句的「原文→译文」历史对 | FR-C1 |
| `{glossary}` | 实体登记表（名称→译法 列表） | FR-C3.1 |
| `{style_notes}` | 当前风格设定摘要 | FR-C3.2 |

## 5. 数据格式规范

### 5.1 LLM 翻译响应 JSON（扩展主 PRD §5.3）

```json
{
  "sentences": [
    {"id": 12, "source": "……", "translation": "……"}
  ],
  "glossary_updates": [
    {"term": "ユキ", "translation": "小雪", "type": "person"}
  ],
  "style_updates": "对话双方为大学前后辈，日语敬体，氛围轻松"
}
```

`glossary_updates` / `style_updates` 允许为空；本地合并逻辑：同 term 后登记覆盖先登记，`style_updates` 非空则整体替换。

### 5.2 会话记忆文件（`memory.json`）

```json
{
  "language_profile": "ja",
  "glossary": [{"term": "ユキ", "translation": "小雪", "type": "person", "last_used_block": 15}],
  "style_notes": "……",
  "updated_at": "2026-10-13T20:30:00"
}
```

存于会话输出目录（主 PRD FR-2.4 结构下新增该文件）。

## 6. 模块改动（对接主 PRD §6）

```
src/nlp/
  llm_client.py       # 无改动：仍只认 base_url/api_key/model
  prompt_engine.py    # 扩展：支持 {context_history}/{glossary}/{style_notes} 变量渲染
  context_memory.py   # 新增：实体登记表、风格摘要的合并/淘汰/持久化/手动编辑接口
  blocker.py          # 新增：语义边界分块（静音间隙 + 句数上限 + 场景信号）
  translate.py        # 改动：按块构造请求，注入历史与记忆，处理 glossary_updates/style_updates 回写
```

主 PRD 架构图中「翻译/语法调度」模块内部细化为：`blocker → prompt_engine(历史+记忆渲染) → llm_client → context_memory(回写)`，对外接口不变，UI 与字幕层无感知。

## 7. 验收标准

| 编号 | 场景 | 通过条件 |
|---|---|---|
| AC-1 | 日语音频含主语省略与代词（如连续对话片段 10 分钟） | 开启上下文后主语补全/代词指向正确率较关闭时明显提升（抽样 50 句人工对比） |
| AC-2 | 同一人物名在会话中出现 ≥ 3 次 | 译名全程一致，且出现在实体登记表中 |
| AC-3 | 关闭三个机制（配置置零/false） | 行为完全退化为无上下文逐句翻译，无报错 |
| AC-4 | 模板中删除 `{glossary}` 变量 | 记忆照常采集但不注入 prompt，日志有降级提示 |
| AC-5 | 块内对齐失败 | 自动重试后逐句兜底，字幕流不中断、不丢句 |
| AC-6 | 成本核算 | 开启默认配置后，token 消耗较无上下文逐句模式增长 ≤ 60%（历史重叠句不重复计费） |

## 8. 已知风险与对策

| 风险 | 对策 |
|---|---|
| 历史/记忆注入增加 token 成本 | 三项机制均可独立开关与调参；AC-6 成本上限约束；记忆容量淘汰机制（FR-C3.5） |
| LLM 误登记错误译名污染后续翻译 | FR-C3.7 手动编辑纠正；同 term 允许后验覆盖（FR-C3.4 合并规则） |
| 风格推断错误（如误判敬简体） | 风格设定可在语言档案中预先指定，档案值优先于 LLM 推断值 |
| 语义分块在持续无静音的语音流（如快速连读）下退化为按句数切分 | 可接受降级，块内上下文仍然有效；句数上限兜底保证不产生超长块 |
| 部分服务商对长 system/context prompt 支持差 | 历史与记忆区块放在 user 消息末尾的可选段；模板可调位置 |

## 9. 范围外（Out of Scope）

- 两遍翻译 / 译文延迟精修替换（two-pass re-translation）
- 独立的共指消解（coreference resolution）预处理模型
- 跨会话的长期记忆（记忆生命周期仅限单会话＋该会话的回放）
- 文档级译文质量自动评测指标的集成
