## 3. 现有实现的关键缺口

### 3.1 悬浮窗与字幕

当前 [src/ui/overlay.py](../src/ui/overlay.py) 只有基础控制条、透明度、穿透、托盘和状态标记，缺少完整 A/B/C 栏和设置页。

当前 [src/ui/subtitle_view.py](../src/ui/subtitle_view.py) 还存在这些限制：

- 每次新增或语法更新都会无条件滚到底部；用户上翻会被抢回。
- 句块和 `_blocks/_order` 无界增长；旧 `SubtitleBuffer` 的容量限制并未覆盖实际新视图。
- 只有含语法数据的句块可单击，无法在回放中对任意句执行 seek。
- 没有当前句高亮、媒体位置跟随、独立 seek 信号。
- 没有翻译中占位、ASR/翻译耗时、通用错误行和系统提示行。
- 当前主流程在翻译返回后才 `recorder.add()`，因此无法先显示“待翻译”句块。

### 3.2 Provider 与换绑

当前架构已经支持顺序换绑，但不等于安全热换绑：

- `ModelSlots.rebind()` 后，未再绑定的本地 Provider 可能立即回收，没有等在途 `chat()` 完成。
- Translator/Grammar 每次 attempt 都重新取 Provider；这是支持新绑定的良好基础，但 Provider 使用没有租约保护。
- 翻译在常规 Blocker 路径中按块串行；语法分析可由多个 worker 并发，两者可共享同一个 Provider 实例。
- Registry 需要避免在全局锁内执行本地进程关闭/等待。
- 同一 Provider 可被翻译槽和语法槽共享；同一 id 的配置编辑以及 A→B→A 都需要实例代际，不能只按 provider id 判断生命周期。
- 本地 `start()` 会同步等待健康检查，不能在 GUI 线程执行。
- `ASRStreamer.stop()` 有 join 超时；退出时不能假设返回后所有翻译请求必然结束。
- 当前语法分析器只在启动时已绑定语法槽才创建；启动后从“未绑定”热绑定语法槽需要调整主程序接线。

### 3.3 配置与密钥

现有全局/档案槽位优先级必须保留：非空 `profile.slots` 覆盖全局 `cfg.slots`，否则使用全局绑定。

注意：

- 设置页只保存全局绑定却遇到档案覆盖时，不得假报“已生效”。
- 现有配置保存能力需要补齐原子写入、完整 Provider 字段保留和 env 密钥防落盘。
- 环境变量填入的 API key 不应因为用户随后保存外观或 Provider 配置而写入 YAML。
- 旧简易 `llm:` 模式与多 Provider 模式的 env/profile 覆盖细节不同，修改配置层时必须保留兼容测试。

### 3.4 回放与文件源

当前 `--replay-session` 只加载句块，不加载媒体。`SessionDocument` 有时间轴但没有媒体路径、时长或播放位置索引。

[src/audio/file_source.py](../src/audio/file_source.py) 是实时模拟采集源：

- 整文件读入、按 30ms 推送，默认按墙上时钟 sleep。
- `finished` 只表示推送结束，不代表 ASR、翻译和语法全部完成。
- `realtime=False` 配合有损 `RingBuffer` 可能覆盖未消费音频，**不能直接当可靠批处理**。
- 不支持完整 mp4/mkv 音轨解码需求。

### 3.5 滚动记忆

[src/nlp/context_memory.py](../src/nlp/context_memory.py) 已有 `RollingMemory.load/save/set_term/remove_term/set_style/clear`，但缺少：

- 应用层加载、编辑 UI 和语言档案校验。
- 严格结构/空字段/重复术语校验。
- 加载后的容量、风格长度等不变量重建。
- `block_counter` 恢复；只恢复 `last_used_block` 会破坏后续 LRU 顺序。
- 线程安全和原子写回现有会话文件。
- 实时编辑与 Translator 当前实例的一致性。

## 4. 推荐统一决策

这些是实施时采用的推荐语义，避免在模块间各自解释需求。

### 4.1 回放单击与语法卡手势分离

需求同时包含“回放点击句子 seek”和“点击有分析句子弹语法卡”。推荐：

- **实时模式**：保留有分析句块单击弹卡。
- **回放模式**：单击任意句块只发 `seek_requested(segment_id)`；通过明确的语法按钮或双击发 `grammar_requested(segment_id)`。
- 不要让同一个 `sentence_activated` 同时触发 seek 和弹卡，也不要让一次手势产生两个结果。
- 同步修订 PRD/设计稿中的单击描述，并添加信号分离测试。

### 4.2 语言档案切换使用“会话滚动”，禁止混写单语言文件

当前 `SessionRecorder` 和 `analysis.<source_lang>.json` 都是单语言会话格式。推荐运行中切换档案时：

1. 暂停接收新 ASR 句。
2. 冲刷旧 Blocker，排空旧语法任务，保存旧会话。
3. 重新解析档案级槽位，重建 Translator/RollingMemory/GrammarAnalyzer/SessionRecorder，并更新 ASR language hint。
4. 创建新的字幕文档和视图，插入“已切换档案”的系统提示，再恢复运行。

旧会话完整保留，新会话使用新档案；不要把两种源语言混写进一个 `analysis.<lang>.json`。自动创建新会话目录可复用现有重名后缀逻辑。

### 4.3 运行/暂停与清除的数据语义

- 实时暂停：停止接收新的 ASR 结果；已在途翻译/语法可自然完成并更新 UI。恢复时清理实时积压和 VAD 状态，从当前音频继续，避免一次性补识别暂停期间的旧音频。
- 回放暂停：只控制 QMediaPlayer，不改变会话文档。
- 清除按钮推荐明确命名为“清空显示”：只清空当前控件，不删除文档、记忆或已落盘文件，并需确认。若未来要“清空会话数据”，应作为另一个显式操作。

### 4.4 档案覆盖槽位时保持诚实

设置页默认只编辑全局 Provider/槽位：

- 若当前档案覆盖某槽，显示“档案覆盖”标识和实际生效值。
- 第一版可禁止在该作用域直接应用全局换绑，并解释原因；不能提示成功却仍沿用旧绑定。
- 若提供“编辑当前档案绑定”，必须是用户显式选择的独立操作，并单独校验/保存档案 YAML；不要隐式引入新的优先级层。

### 4.5 本地到本地换绑优先安全而非并发启动

本地 A→本地 B 可能同时遇到端口冲突和 VRAM 双重占用。推荐按槽位提供 `switching` 状态：

- 云端或无资源冲突的候选可先在 worker 中准备/健康检查，再原子发布。
- 需要停用旧本地实例时，先阻止该槽的新 acquire，让新请求在 worker 侧等待；旧租约归零并回收旧实例后再启动候选。
- GUI 只显示 applying/draining/failed/ready，不等待网络或进程。
- 等待期间不得让 GUI 卡死，也不能通过不断接受旧绑定新请求导致排空饥饿。

### 4.6 `style_preset` 采用一致锁定规则

语言档案设置 `style_preset` 时，风格编辑区只读并显示来源；人工编辑和 LLM 更新都不能暗中覆盖档案预设。未设预设时，人工编辑当前记忆可立即生效。

### 阶段 2：Provider 租约、安全热换绑与设置控制器

修改 [src/nlp/providers/registry.py](../src/nlp/providers/registry.py)、[src/nlp/slots.py](../src/nlp/slots.py)、[src/nlp/providers/llama_cpp_local.py](../src/nlp/providers/llama_cpp_local.py)：

- Registry 每个 Provider **实例**维护 `generation/state/active_calls`，状态至少含 active/retiring/closed。
- 槽位 acquire 和绑定发布使用统一的短锁顺序；请求释放租约必须在 `finally` 中执行。
- 推荐消费接口：

```python
with slots.acquire(SLOT_TRANSLATION) as provider:
    if provider is not None:
        response = provider.chat(...)
```

- 换绑发布后，旧代进入 retiring；只有不再被任何槽引用且 `active_calls == 0` 才关闭。
- close/start/health 等待不得持有 Registry 全局锁；旧代可由专门回收线程关闭，避免请求 worker 被本地进程关闭阻塞。
- 同 id 编辑创建新代，A→B→A 也不能复活正在退休的旧 A。
- `close_all()` 必须先停止生产者，再等待活动租约；应用退出不能提前关闭仍在使用的本地 Provider。

修改 [src/nlp/translate.py](../src/nlp/translate.py) 和 [src/nlp/grammar.py](../src/nlp/grammar.py)，让实际 `chat()` 都在租约内完成。保留每次新 attempt 可解析当前绑定的行为；租约保护单次 Provider 请求，重试可使用已发布的新绑定。

修改 [src/main.py](../src/main.py)：

- 语法分析器在 slots 可用时始终可创建；自动 `--grammar` 提交前检查当前绑定，未绑定时不制造必然失败任务。
- 热绑定/解绑后同步更新 overlay 的语法入口状态。
- 退出顺序仍为停采集/ASR → Blocker flush → Grammar drain → 保存 → Registry 安全关闭，并补上当 ASR join 超时后的在途翻译保护。

- CLI 推荐 `--replay-session <dir> --media <path>`，同时提供“打开媒体”入口；不必为了媒体路径改变现有五类会话文件格式。
- `positionChanged` 转换为秒，用 `SessionDocument.segment_at()` 查当前句；只在当前 ID 变化时高亮和跟随滚动。
- 单击 seek 使用 `player.setPosition(round(segment.start * 1000))`，句间空白清除当前高亮。
- 保留第 4.1 节的独立语法手势。
- 外部 SRT 按完整块读取并保留多行，不再只取前两行；内部双语格式保持向后兼容。
- offscreen 用假媒体时钟/假 player 验证同步，不把模块可导入当作真实编解码验收。

### 阶段 5：真正的离线批处理

新增独立解码与离线编排模块，例如 [src/audio/decoder.py](../src/audio/decoder.py) 和 `src/offline/runner.py`；保留 [src/audio/file_source.py](../src/audio/file_source.py) 的实时模拟职责。

推荐管线：

```text
PyAV 流式解码
  → 有界阻塞音频队列（背压，不丢样本）
  → 复用 VAD/ASR 断句状态，显式 finish/EOF
  → Blocker（offline=20 句、autoflush=False）
  → 顺序 Translator（保持历史/记忆顺序）
  → 有界 GrammarAnalyzer
  → drain 完成后 SessionRecorder.save()
```

具体要求：

- 在 [pyproject.toml](../pyproject.toml) 显式声明直接使用的 `av`，不要依赖它恰好是 faster-whisper 的传递依赖。
- 解码为 16kHz 单声道 float32 流式块，处理无音轨、损坏文件和中文路径。
- 不使用实时 `RingBuffer`，不使用固定 0.5s/3s 作为完成判断。
- 可把现有 [src/asr/streamer.py](../src/asr/streamer.py) 的 VAD/ASR 状态提炼为实时和离线共用处理器，避免复制两套断句逻辑。
- 离线翻译可在 ASR 消费线程按块顺序执行，让有界音频队列自然背压；不要并发翻译块破坏滚动记忆顺序。
- EOF 顺序：解码结束 → ASR flush → Blocker flush → 翻译全部完成 → Grammar drain → 保存 → 关闭 Provider。
- CLI 可支持一个或多个 `--batch` 输入、进度、Ctrl+C 取消和逐文件失败隔离；`max_sentences_offline=20` 必须实际生效。
- 保持 `--source file` 的实时模拟语义不变，不让两种模式共享有损缓冲假设。

### 阶段 6：记忆编辑与设置页收尾

修改 [src/nlp/context_memory.py](../src/nlp/context_memory.py)，新增记忆编辑控件（可放 [src/ui/settings.py](../src/ui/settings.py) 或独立 `memory_view.py`）：

- 根对象、glossary 数组、term/translation/type/last_used_block 做严格校验；空字段和重复 term 给出明确行号/条目错误。
- 加载后重新执行容量和风格长度不变量；`block_counter` 至少恢复为现有最大 `last_used_block`。
- 所有读写、prompt 快照和保存使用同一把可重入锁，避免 GUI 与翻译线程并发修改。
- 保存现有会话的 `memory.json` 使用原子替换，不通过 `SessionRecorder.save()` 新建日期目录。
- 实时模式编辑 `Translator.memory` 的同一实例；下一次 prompt 必须立即看到新术语/风格。
- 加载时校验 `language_profile`，防止日语记忆无声注入英语会话。
- UI 支持术语增删改、风格编辑、清空确认、未保存标记和重新加载；预设存在时风格区按第 4.6 节只读。
- 设置页同时提供 prompt 目录入口和恢复默认入口；恢复用户模板前需确认并保留备份，利用现有 PromptEngine mtime 热重载。

## 6. 测试计划

每阶段先运行现有全量测试，再添加对应测试；170 passed 是交接基线，不是未来硬编码目标数。

### Provider/配置

- 用 Event 阻塞旧 Provider `chat()`：换绑后新请求使用新实例，旧实例只在释放后才关闭且恰好一次。
- 同一 Provider 双槽共享、A→B→A、同 id 配置编辑、异常路径租约释放。
- close 不持全局锁；本地启动/健康检查不阻塞 Qt GUI。
- 本地到本地冲突时，新 acquire 在 worker 等待，旧请求不会饥饿排空。
- 健康检查/原子保存失败不发布；env key 不落盘，timeout/max_retries 等字段不丢失。
- 档案覆盖时 UI 不假报全局换绑生效。
- 退出时有慢翻译/慢语法请求，Registry 不提前 close。

### UI/外观/指标

- A 栏开关、紧凑高度、字幕显隐、清除/退出确认、托盘状态。
- B 栏能力过滤、未绑定样式、加载禁点、档案覆盖和状态刷新。
- C 栏用伪指标验证每秒定时器、字段显隐和 `<2000MB` 告警，不访问真实 GPU。
- D 区占位按 ID 更新、错误/系统行、四种显示顺序、控件容量上限。
- 上翻后新句不抢滚动条，回到底部恢复；纯分析更新不触发抢底。
- 外观保存→重载→重建窗口，档案覆盖、恢复默认、独立原/译文样式和背景透明度。
- 中/英资源缺失 key 有安全回退。

### 回放

- 假时钟驱动句首/句尾/句间空白、暂停 seek、连续 seek 和末尾。
- 无分析句也可 seek；一次手势不会同时 seek 和弹卡；语法卡仍可独立打开。
- 批量加载不自动跳底，当前句变化才跟随。
- 外部多行 SRT、旧内部双语 SRT 和稳定 ID 回归。
- 媒体加载错误有可见提示；无媒体预览保持可用。

### 离线批处理

- 构造超过旧 RingBuffer 容量的长输入，验证慢 ASR/慢翻译下不丢音频。
- 显式 EOF 能冲刷尾句/尾块，无固定 sleep 完成假设。
- 离线 20 句上限、禁用墙上时钟 autoflush、翻译块顺序和记忆回写顺序。
- 保存发生在全部翻译/语法完成后；取消和单文件失败不阻塞后续文件。
- 可选真实 whisper E2E 仍单独以 `ASR2CLASS_E2E=1` 运行，不把 skipped 写成通过。

### 记忆

- 畸形 JSON、空字段、重复 term、容量/风格长度、LRU 计数恢复、语言档案不匹配。
- GUI 编辑与翻译读取并发、原子保存失败保留原文件。
- 编辑当前 Translator.memory 后下一 prompt 立即生效；style_preset 只读规则一致。

通用回归命令：

```bash
QT_QPA_PLATFORM=offscreen uv run --no-sync pytest -q -rs
```

## 7. Windows 真机验收清单
