## 1. 项目背景与目标

用户需要一款运行在 **Windows 笔记本（i5-12500H + RTX 3060 6GB + 16GB RAM）** 上的开源技术栈应用，实现：

1. 实时语音识别（ASR）＋可配置模型翻译；
2. 识别与翻译结果落盘，并生成带时间轴的字幕文件（SRT/VTT）；
3. 播放音视频时以悬浮窗形式实时滚动显示字幕；
4. 外语学习增强：字幕生成阶段可调用语法模型标注语法点、分析句子结构；播放时可与字幕交互，以悬浮卡片形式逐句学习；
5. 通过上下文窗口、块级翻译和滚动记忆，改善跨句指代、术语一致性及语域稳定性。

**核心约束**：

- ASR、耳语 VAD 和用户显式选择的本地翻译 Provider 可适量调用 GPU，均受 §4.2 显存预算约束；
- 翻译与语法分析采用**独立模型槽位**：可绑定云端 OpenAI 兼容服务，也可绑定本地 OpenAI 兼容端点；不得自动进行“云端超时 → 切换本地模型”的故障转移；
- 云端翻译不可用时可降级为仅显示原文，云端语法不可用时仅停用语法功能；本地 Provider 不受互联网断网影响；
- **所有面向 LLM 的 prompt 均为用户可编辑的外部模板文件，代码中不得硬编码任何 prompt 全文**；
- **语言学习配置按语言完全隔离**（见 §5.3 语言档案），日语为当前主要学习语言，架构必须支持后续仅新增配置和模板即可添加新语言。

## 2. 名词定义

| 术语 | 含义 |
|---|---|
| ASR | 自动语音识别（Automatic Speech Recognition） |
| 语言档案（Language Profile） | 一种语言的全部学习配置集合：语言对、ASR 参数、模型槽位覆盖、上下文配置、prompt、语法卡声明、等级体系等，以独立 YAML 文件存在 |
| 语言对（Language Pair） | 源语言（被识别的语音）＋目标语言（翻译/讲解用语）的组合，由语言档案定义 |
| Provider（模型提供方） | 一个声明式的 OpenAI 兼容模型端点，可为云服务、llama.cpp server 或 vLLM；具有唯一 id 和能力标签 |
| 模型槽位（Model Slot） | 翻译或语法分析的逻辑插槽，按 provider id 绑定；档案覆盖优先于全局绑定 |
| 翻译块（Block） | 一次翻译请求中包含的句子集合，块内句子互相可见，并与历史窗口共同提供上下文 |
| 滚动记忆（Rolling Memory） | 随会话累积的实体译名表和风格摘要，在同次翻译响应中更新并跨块注入 |
| 悬浮窗 | 置顶、半透明、可点击穿透的桌面字幕窗口 |
| 语法卡 | 点击某句字幕后弹出的悬浮卡片，展示句子结构、语法点、词汇讲解，展示内容随语言档案而变 |

### FR-C 上下文感知翻译

本节约束已合并自《上下文感知翻译-专项需求文档》。采用轻量的“滑动上下文窗口＋块级整体翻译＋滚动记忆”，不采用两遍翻译或独立共指消解模型。

| 编号 | 需求 | 优先级 | 当前状态 |
|---|---|---|---|
| FR-C1 | 翻译第 N 块时注入前块尾部 K 句“原文＋已确认译文”，K 默认 3、可按档案覆盖；历史受 token 上限约束，超出裁最早内容，且只输出当前块译文 | P0/P1 | 已实现 |
| FR-C2 | 按语义边界成块：静音间隙、句数上限或空闲超时触发，默认最多 8 句；块内多句一次请求并逐句对齐，重叠历史不重复翻译 | P0 | 核心已实现；场景切换信号及完整离线批处理待后续 |
| FR-C3 | 维护实体译名表和风格摘要，通过 `{glossary}` / `{style_notes}` 注入；同次响应返回 `glossary_updates` / `style_updates`，本地合并、LRU 淘汰并保存 `memory.json` | P0/P1 | 核心与持久化已实现；回放导入和图形编辑界面待后续 |
| FR-C4 | 三种机制可独立开关；模板缺少对应变量时该机制自动停用并记录日志；整块解析/对齐失败重试 1 次，再拆成逐句无上下文翻译，单句仍失败则保留原文 | P0 | 已实现 |
| FR-C4.4 | 语法缓存 key 纳入上下文配置摘要，避免上下文策略变化后复用旧分析 | P1 | 待随 FR-4.5 实现 |

默认配置：

```yaml
context:
  tail_sentences: 3
  history_max_tokens: 512
  block:
    max_sentences: 8
    max_sentences_offline: 20
    silence_gap_sec: 1.5
  memory:
    enabled: true
    glossary_max_entries: 100
    style_max_chars: 200
```

## 4. 技术栈与 GPU 使用策略

### 4.1 技术栈

| 层 | 选型 | 说明 |
|---|---|---|
| ASR 引擎 | **faster-whisper**（GPU: CUDA `int8_float16`；CPU: `int8`） | 默认 small；medium 需显式配置。FunASR SenseVoiceSmall 保留为中文备选后端 |
| VAD | **Silero VAD＋Whisper-Vad-EncDec-ASMR ONNX** | 后端可插拔；后者面向耳语/软语，支持 CPU/CUDA 和流式增量推理 |
| 翻译/语法模型 | **Provider Registry＋独立双槽位** | 云端 OpenAI 兼容 API、本地 llama.cpp server 或 vLLM；无默认服务商，不做自动云端到本地故障转移 |
| GUI | **PyQt6** | 当前为基础悬浮窗；回放、语法卡、完整设置页随 M3 |
| 音频采集 | sounddevice（麦克风）＋ pyaudiowpatch（WASAPI loopback）＋ soundfile（文件模拟） | mic/loopback 在 Windows 真机运行；模块延迟导入以支持 WSL 测试 |
| 字幕 | pysrt＋项目内 txt/SRT/JSON writer | 当前已生成 txt、SRT、分析骨架和记忆文件 |
| 配置管理 | 分层 YAML：全局 providers/slots → 语言档案覆盖 → 外部 prompts；环境变量覆盖密钥 | `config.yaml` 和模型文件不入库，API key 不入日志 |
| 语言/运行时 | **Python 3.12，uv 锁定依赖** | Windows 与 WSL 使用各自平台依赖 |
| 打包 | PyInstaller 单目录版 | 可选，M4 |

### 4.2 GPU 使用策略（重要）

设备有 RTX 3060 6GB，用户还会同时开浏览器/播放器，**GPU 只准适量调用**：

| 规则 | 说明 |
|---|---|
| ASR 显存预算 | ASR 相关占用目标 ≤ 2.5GB，并保留 ≥ 2GB 空闲显存给其他应用；启动时检测，不足则降级更小模型或 CPU |
| 默认配置 | GPU：faster-whisper small `int8_float16`；medium 仅在配置中显式开启 |
| 本地 Provider | 本地翻译模型必须显式声明和绑定；按其 `vram_budget_mb` 做启动预检，空闲显存低于“预算＋2GB 保留量”时明确警告，建议改 CPU 或换绑，不得静默抢占 |
| 合计占用 | ASR、whisper_asmr VAD 与本地翻译模型共同运行时仍须保留 ≥ 2GB；显存紧张时可单独设 `vad.device: cpu` 或改用云端 Provider |
| CPU 兜底 | ASR 和 whisper_asmr 均支持纯 CPU；CUDA 初始化失败自动回落并提示。本地 llama.cpp 的 CPU/GPU 卸载由用户配置的 server_args 控制 |
| 资源回收 | 本地托管 Provider 换绑出所有槽位或应用退出时必须回收子进程、释放显存 |
| 禁止事项 | 禁止未经用户确认升级模型档位或常驻大型模型；禁止 large-v3＋大型本地 LLM 的重型组合；禁止云端超时后自动换绑本地模型 |

### 4.3 开发环境、依赖与模型获取

- WSL2 用于开发和自动化测试；无 Windows 音频栈时，mic/loopback 不参与测试，PyQt6 使用 offscreen。**Windows 11 仍是音频、CUDA、悬浮窗交互和性能指标的正式验收环境。**
- Windows 锁定 CUDA 12/cuDNN 9 相关依赖；whisper_asmr GPU 使用 `onnxruntime-gpu==1.26.*`，启动时注册所需 DLL 目录，失败自动回退 CPU。
- HuggingFace 直连不可用时支持 `HF_ENDPOINT=https://hf-mirror.com`、`HF_HUB_DISABLE_XET=1`；GGUF 下载还应支持 ModelScope 回退。
- 入库文件仅包含 `config/config.example.yaml`；本地 `config/config.yaml`、API key、GGUF/ONNX 模型和输出文件不得提交版本库。

## 5. 数据格式规范

### 5.1 标准字幕（SRT）

```text
1
00:00:01,200 --> 00:00:04,500
原文内容

2
00:00:04,600 --> 00:00:08,000
原文内容
译文内容
```

### 5.2 语法分析 JSON——语言相关部分由档案声明

通用骨架（所有语言一致）：

```json
{
  "version": "1.0",
  "language_profile": "ja",
  "source_lang": "ja",
  "target_lang": "zh",
  "prompt_template_version": 3,
  "segments": [
    {
      "id": 1,
      "start": "00:00:01,200",
      "end": "00:00:04,500",
      "source": "……",
      "translation": "……",
      "structure": null,
      "grammar_points": [],
      "vocabulary": [],
      "extra": {}
    }
  ]
}
```

M2 已落地上述骨架。M3 填充后，`structure` / `grammar_points` / `vocabulary` / `extra` 的内部字段由语言档案 prompt 定义，代码只负责透传和按声明渲染。日语示例可使用假名读音、助词、JLPT；英语可使用音标、时态、CEFR。**代码中不得出现任何语言特定语法字段名。**

### 5.3 语言档案（`config/languages/<lang>.yaml`）示例

```yaml
language: ja
display_name: 日语
language_pair:
  source: ja
  target: zh
asr:
  language_hint: ja
llm: {}                 # 旧简易模式覆盖；多 Provider 推荐使用 slots
slots: {}               # 可选 translation/grammar 覆盖，留空沿用全局
context: {}             # 可逐项覆盖全局上下文配置
style_preset: ""        # 非空时锁定风格，优先于模型推断
prompts:
  translate: ja/translate.txt
  # translate_insttrans: ja/translate_insttrans.txt
  # grammar: ja/grammar.txt
subtitle:
  display_order: source_first
# M3/M4 学习展示声明：
grammar_card:
  sections: [structure, grammar_points, vocabulary]
vocabulary_export:
  fields: [word, reading, pos, meaning, jlpt, sentence, timestamp]
```

### 5.4 Provider 与模型调用约定

Provider 和槽位的全局配置骨架：

```yaml
providers:
  - id: local-translator
    type: llama_cpp_server
    base_url: "http://127.0.0.1:8080/v1"
    api_key: "EMPTY"
    model: "local-translator"
    capabilities: [translation, glossary_constraint]
    local:
      managed: true
      gguf_path: "models/translator.gguf"
      vram_budget_mb: 1500
  - id: cloud-general
    type: openai_compatible
    base_url: "https://your-provider.example.com/v1"
    api_key: ""
    model: "your-model-name"
    capabilities: [translation, grammar]
slots:
  translation: local-translator
  grammar: cloud-general   # 留空则语法功能停用
```

调用规则：

- 翻译与语法按槽位独立调用，**不再强制合并为一次请求**；翻译按块批处理，语法分析为异步后台任务，不阻塞字幕主流程；
- 通用翻译 Provider 优先使用 `response_format: json_object`，服务商返回 400 表示不支持时自动退化为普通请求，由模板保证格式说明；
- 通用翻译响应契约：

```json
{
  "sentences": [
    {"id": 12, "source": "……", "translation": "……"}
  ],
  "glossary_updates": [
    {"term": "ユキ", "translation": "小雪", "type": "person"}
  ],
  "style_updates": "对话双方为大学前后辈，敬体，氛围轻松"
}
```

- 声明 `glossary_constraint` 的 Provider 可使用 instTrans 纯文本契约：术语表映射到【硬性要求】、风格映射到【注意】，响应按行与当前块句子对齐；不得强制其返回通用 JSON；
- 整块解析/对齐失败时重试 1 次，再拆为逐句无上下文翻译；单句仍失败则保留原文。语法解析失败时该句 analysis 为 null，不弹语法卡；
- 所有请求的实际 prompt 可在调试日志查看，但 API key 禁止输出。

### 5.5 会话滚动记忆（`memory.json`）

```json
{
  "language_profile": "ja",
  "glossary": [
    {"term": "ユキ", "translation": "小雪", "type": "person", "last_used_block": 15}
  ],
  "style_notes": "……",
  "updated_at": "2026-10-16T20:30:00"
}
```

记忆生命周期默认仅限当前会话及该会话回放；同 term 后登记覆盖先登记，超出容量按 LRU 淘汰，风格摘要整体替换并受长度限制。

## 9. 已知风险与对策

| 风险 | 对策 |
|---|---|
| RTX 3060 与浏览器/播放器争抢显存 | ASR 预算＋本地 Provider 独立预算＋合计保留量检查；VAD/ASR/本地模型可分别切 CPU 或换绑 |
| 部分声卡/驱动 loopback 不可用 | Windows M1 真机验证；提供设备枚举和明确排障指引，麦克风兜底 |
| small 模型对日语快语速/动漫腔识别不佳 | 显式升 medium；ASR 后端抽象保留 FunASR 备选 |
| 耳语/软语被 Silero 漏检 | 使用 whisper_asmr，可调阈值和设备；加载失败回退 Silero |
| Whisper 在静音/BGM 中产生结束语幻觉 | 质量阈值＋压缩比门控＋用户可编辑短语黑名单；流式识别默认不以历史文本条件化 |
| 不同 Provider 对 `response_format` 支持不一 | 400 自动退化普通请求；模板自带 JSON 说明；块重试和逐句降级 |
| 本地/专用翻译模型不支持通用 JSON | 以能力标签选择 instTrans 纯文本契约，按行对齐，不强求通用响应格式 |
| 用户改坏 prompt 导致输出异常 | 保留 `_default/` 模板和恢复默认入口；未提供变量时报告文件与行号；调试日志暴露实际 prompt |
| 上下文记忆误登记、历史污染或 token 增长 | 记忆容量/LRU/风格长度限制；档案 style_preset；手动编辑接口；历史回写卫生校验；各机制独立开关 |
| WSL 缺少音频栈、GitHub/HuggingFace 直连受限 | WSL 只做开发和 offscreen 测试；Windows 真机验收；HF 镜像＋禁用 xet＋ModelScope 回退 |
| CUDA/cuDNN/onnxruntime 版本或 DLL 不匹配 | uv 锁定 Windows CUDA 12 依赖；启动注册 DLL、预热自检和针对性诊断；失败自动回退 CPU |
| 本地 llama-server 启动失败或残留进程 | 健康检查、明确错误提示、退出/换绑回收；允许用户自配 server_bin 和 server_args |
| 长会话内存/显存增长 | 环形音频缓冲、滚动字幕容量限制、记忆 LRU、旧音频块及时释放 |
| API 费用 | 块级请求＋上下文 token 上限＋模板/Provider/上下文感知缓存（M4）；UI 显示 token 用量估算 |

## 10. 范围外（Out of Scope）

- 多说话人分离（diarization）；
- 实时配音/TTS 输出；
- 云端同步、多设备账号体系；
- 移动端支持；
- large-v3 级 ASR 或未经显式确认的大型本地模型常驻 GPU；
- 云端超时后自动切换本地 Provider 的故障转移链；
- 两遍翻译、独立共指消解预处理、跨会话长期记忆；
- 本地模型训练/微调及通用聊天助手能力。
